# FinalShell 产品功能与行为研究报告

## 1. 结论摘要

FinalShell 不是单纯的 SSH 终端，而是将连接管理、交互式 Shell、远程文件管理、文本编辑、快捷命令、代理/隧道、系统与网络工具、配置同步整合在一个 Java 桌面程序中的运维客户端。

此次静态证据支持以“多协议远程工作台”作为重写产品定位。第一版应优先交付 SSH、终端、SFTP 和安全的本地配置；同步、抓包、网络穿透等能力应隔离为后续可选模块，不能拖慢核心终端的交付。

## 3. 已观察的程序结构

### 3.1 启动与运行时

- `finalshell.exe` 是 PE32/x86 Windows 原生启动器。REA 观察到注册表读写、进程创建、动态库加载、文件操作和窗口 API 的导入。
- `finalshell.jar` 的 Manifest 声明 `Main-Class: st`，并引用 `lib-run/bcprov.jar`。
- 入口 `st.main` 通过 `com.c` 的反射分发进入真实初始化逻辑，而不是直接显示主窗口。
- `finalshelltest.bat` 使用捆绑的 Java 17.0.7，以 `-Dsun.java2d.opengl=false -Dsun.java2d.d3d=false` 和堆空间回收参数运行 JAR。
- JAR 包含 Swing/FlatLaf、MigLayout、RSyntaxTextArea、Netty、Apache HttpClient、OSHI、Pcap4j、SOCKS、JTermios 和 Bouncy Castle 等组件。

因此，产品应以“原生外壳 + 跨平台核心 + 图形工作台”理解；重写时不需要照搬 Java 反射层。

### 3.2 界面与工作区

证据包括 Swing 主窗口、系统托盘、选项卡、树/表格、文件选择器、主题资源及语法编辑器。配置键还显示可保存侧栏、布局、窗口尺寸、标签选择、终端字体、主题、背景图、鼠标操作及快捷键。

已观察编辑器使用 RSyntaxTextArea，支持语法高亮、代码折叠、匹配内容标记、自动换行和保存。配置中区分编辑器类型和非文本文件扩展名。

### 3.3 连接与远程会话

连接配置以独立 `conn` 目录和树形管理界面呈现。代理配置、密钥列表、近期探测主机和连接筛选是独立的设置类别。

网络相关类显示 TCP/UDP Socket、监听 Socket、SOCKS 组件及多种网络通道实现。由于协议字符串和反射符号被混淆，SSH 具体算法协商、跳板链语义及所有支持协议的完整清单仍未验证。

### 3.4 文件与传输

文件模型同时具有名称、显示名称、绝对路径、大小、修改时间、本地 File 对象、类型及状态字段。代码存在目录树、路径历史、上传/下载最近目录、文件历史以及文本保存路径。

安装目录带有 `curl.exe`，同时 JAR 内有 Socket、HTTP、归档及文件流代码。可以确认产品处理本地/远程文件和路径状态；不能仅根据这些组件推断所有下载都经由 `curl.exe`。

### 3.5 命令生产力

配置键明确包括快捷命令、命令历史、分组选择、命令提示、命令输入缓存过期时间、发送后清空输入、命令输入显隐、完整路径显示以及两组“发送到”选项。

这说明命令面板不是简单输入框，而是具有历史、分组、缓存、提示及多目标分发的产品模块。

### 3.6 监控、诊断与网络工具

- OSHI 组件提供操作系统、硬件和 JNA 访问能力。
- Pcap4j 被多个应用类直接调用，使用 `openLive` 和混杂模式；安装目录附带 `winpcap_install.exe`。
- 存在 ICMP、端口/监听 Socket、UDP 和 HTTP 工具代码。
- `ipdata.dat` 表明产品捆绑 IP 地理或地址段数据；具体供应方与查询精度未验证。

抓包和网络测试应设计为显式启动、可停止、受权限控制的功能，而不是随终端静默开启。

### 3.7 同步、备份与更新

安装目录存在 `sync/db_.json`、`sync/deletions.json` 和 `backup/app_config/<timestamp>.json`。这说明配置同步至少考虑数据库状态与删除记录，配置变更还具有按时间戳保留的备份。

程序有 HTTP 客户端、更新器和自启动配置。HTTP 客户端关闭自动重试和自动重定向，使用系统默认 TLS 上下文及连接池。同步协议、服务端、删除冲突规则、更新签名校验及触发时机均未被静态证据完整证明。

## 5. 关键运行机制模型

### 5.1 启动

静态顺序为：原生启动器加载系统资源并创建 Java 进程，Java 读取 JAR，入口通过反射完成初始化，最终建立 Swing 工作区。批处理是另一条明确的 Java 启动路径。

重写后的合理模型为：原生 GUI 初始化，读取设置，创建应用服务，后台初始化会话管理器；不得因云同步、更新检查或可选网络工具阻塞主界面。

### 5.2 会话

工作台事件应进入会话管理器，由会话管理器持有连接状态机、终端通道和文件通道。I/O 在后台执行，界面只消费有界事件流；关闭标签、主动断开、远端 EOF、认证失败和网络超时应产生不同状态。

### 5.3 文件与编辑

文件列表和传输均为异步任务。编辑器必须保留打开时的远端文件身份和修订信息，保存时检测远端变化；不能用一个本地路径覆盖整个远端目录。

### 5.4 数据持久化

观察到的数据类型包括：连接/密钥/代理、快捷命令和命令历史、UI 布局与偏好、上传下载路径、同步状态与删除记录、时间戳备份、图片缓存和 IP 数据。

重写版必须把“普通设置”“敏感凭据”“会话历史”“可重建缓存”分开存储，并明确定义导出、备份和同步是否包含每类数据。

## 6. 数据行为清单

| 数据 | 静态证据 | 重写要求 |
| --- | --- | --- |
| 密码与密钥引用 | 配置键 `password`、`secret_key_list` | 不复制原存储方案；使用操作系统密钥库 |
| 连接与代理 | `conn`、`proxy_list`、`recent_detect_host` | 非敏感字段可版本化；凭据单独引用 |
| 命令与历史 | `quick_commands`、`cmd_history`、`command_input` | 默认本地保存，提供禁用、清除和脱敏导出 |
| 布局与主题 | `layout`、`layout_config`、字体、主题、背景、快捷键 | 版本化、容错恢复、未知字段向前兼容 |
| 文件传输偏好 | 上传下载最近目录、文件历史 | 只保存用户明确需要的历史 |
| 同步 | `sync/db_.json`、`deletions.json` | 使用修订号和删除墓碑，冲突可见，不默认上传敏感信息 |
| 备份 | `backup/app_config/<timestamp>.json` | 原子写入、保留上限、恢复前再备份 |
| 网络与更新 | 连接池 HTTP、更新器 | HTTPS、显式代理策略、包签名验证、失败不阻塞核心 |
| 网络捕获 | Pcap4j 混杂模式 | 显式授权、显示接口/范围、限制保留与导出 |

## 7. 已回答、部分回答与未解决

### 已回答

- 技术形态：Windows 原生启动器加 Java 17/Swing 桌面程序。
- 产品定位：连接、终端、文件、编辑、命令、网络/系统工具和配置管理的一体化工作台。
- 主要界面状态、命令面板、编辑器、托盘和备份/同步目录的存在。
- 启动器能力边界、JAR 入口、关键第三方组件和部分实际调用。

### 部分回答

- SSH/SFTP 的完整协议细节、算法及跳板/隧道配置模型。
- 云同步请求格式、账号绑定、合并算法、服务端错误处理。
- 远程监控具体采集命令、频率及数据展示形式。
- 更新包来源、完整校验流程和自动启动注册细节。
- 所有对话框、菜单、协议类型和平台差异的逐项清单。

### 未解决及原因

- 实际运行时的网络目的地址、请求内容、连接顺序和异常恢复：需要隔离测试环境运行时观测。
- 原连接凭据的实际加密及兼容性迁移：未读取用户敏感数据，且混淆阻碍完整静态恢复。
- 原 UI 的精确视觉及交互一致性：需要用户明确授权的界面走查。

后续规范不把这些未知项当作既定事实，也不要求兼容原服务端或原加密格式。
